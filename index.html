1. Overview & Final Structure

The assignment is a three-page application: a home page (login), a data-entry form (admin only) and a data view (any logged-in user), backed by data/students.csv. It follows the three-layer structure used in the class demos:

Browser request
   └─> public/index.php        Front controller: session_start + requires + route by ?action=
         └─> src/action_controller.php   Action controller: picks the view (showHome/showForm/showData/processForm)
               └─> templates/*.php      View templates: each requires header.php to compose the page
assign3_starter/
├── public/
│   └── index.php                 ← Front controller (single entry point)
├── src/
│   ├── sessionManager.php        ← login, session, authN & authZ (isAdmin added)
│   ├── file_utility.php          ← readData / writeData
│   ├── validation.php            ← validate() form validation
│   └── action_controller.php     ← showHome / showForm / showData / processForm
├── templates/
│   ├── header.php                ← header + navigation (shared by all pages)
│   ├── home.php                  ← home page (login form by default)
│   ├── form.php                  ← data-entry form
│   └── data.php                  ← data view
├── data/
│   └── students.csv              ← data file (absent at startup, created on first write)
└── html_examples/                ← static reference pages (read-only, not executed)

Test accounts (provided in getUsers(), must not be changed): admin / Adm@3280 and user / User@3280.

2. Request Flow (Routing Table)

index.php routes with switch ($action), matching the week05 demo (CH16) front-controller style:

URLHandlerResult
/ or anything elsedefault → showHome('')Login form when logged out (Fig. 1); authorization text when logged in (Fig. 4)
/?action=login POSTprocessLogin()admin → form page (Fig. 3); user → data page (Fig. 12); failure → home + error (Fig. 2)
/?action=login GETshowHome('')Same as home
/?action=form GET / POSTshowForm([]) / processForm(DATA_FILE)Admin only; user or guest is sent back home (Fig. 12 note)
/?action=datashowData(readData(DATA_FILE))Visible to any logged-in user (Figs. 5, 9, 12)
/?action=logoutlogout()Clears $_SESSION, back home (Fig. 11)
Why require paths use __DIR__: relative paths starting with ../ are resolved only against the PHP process working directory, which breaks if the server is started from another folder. __DIR__ always points at the file's own directory. The data file path is defined once as DATA_FILE in index.php, so processLogin() (whose signature cannot change) can also use it.

3.3 src/file_utility.php — file I/O

Original state: two empty functions with comments.

  • addedreadData(): file_exists() check first — missing file returns [] (which triggers the Fig. 5 message); otherwise fopen(..., 'r') + fgetcsv loop building an array of arrays, skipping empty lines
  • addedwriteData(): file_exists() check — if missing, touch() creates it first, then file_put_contents($fileName, $str . PHP_EOL, FILE_APPEND | LOCK_EX) appends one line
Why create-then-append? The starter comment says "if the file does not exist, it should not write any data", but the assignment also requires students.csv to be absent at startup while Fig. 10 shows data saved after the first submit. Taking the figures as authoritative, the file is created on demand; the reasoning is documented in the code comments.

3.5 src/action_controller.php — action controller

Original state: four empty functions (signatures must not change).

  • addedshowHome / showForm / showData: each require_once __DIR__ . '/../templates/xxx.php'; (templates run inside function scope, so the parameters $loginError / $errors / $dataArray are directly visible in the templates)
  • addedprocessForm($dataFileName): validate() first; on errors → showForm($errors) (Fig. 6); otherwise build one CSV line Name,ID,Email,Dept,Status (the 5 fields of Fig. 10) → writeData() → $GLOBALS['formSaved'] = true; → showForm([]) (Fig. 8: disabled controls + confirmation text)
Why $GLOBALS['formSaved']? The success view needs the same form template but disabled, and showForm($errors)'s signature cannot change — so a global flag is set and read in form.php via $GLOBALS['formSaved'] ?? false. Also note the CSV has no Term field: Fig. 10 stores 5 columns and, per Fig. 9, the "Term" table column actually shows the email.

Short answer: no original assignment comment was ever deleted. The only original content replaced in the whole project is 2 static placeholders inside templates/header.php:

5. From html_examples to templates (making the static code work)

The five files in html_examples/ are static renderings showing what the final HTML should look like; templates/ holds the dynamic versions. The mapping:

html_examples fileContentGoes to
template_header.htmlHeader part (nav + user area)templates/header.php (starter already gives the body; only conditionals + dynamic output were needed)
home_complete.htmlComplete home = header + home composedUsed to verify the header.php + home.php composition matches
template_home.htmlLower half of home (h1 + error box + login form)Body of templates/home.php
template_form.htmlLower half of form (error box + form)Body of templates/form.php
template_data.htmlLower half of data page (h1 + table)Body of templates/data.php

The 4-step recipe (static HTML → working PHP template)

  1. Locate the static block you need (error box, form, table, nav items) in html_examples.
  2. Paste it into templates/xxx.php after require_once 'header.php'; and before the closing </div></body></html>. At this point it already renders statically.
  3. Make the data dynamic: swap hard-coded sample values for <?= $var ?>; replace repeated lines (options, table rows, error li) with a foreach.
  4. Add control structures: wrap blocks in <?php if ...: ?> ... <?php endif; ?> to control visibility / selected / checked / disabled.

Why pasting alone already works

  • Templates are pulled in by showHome()/showForm()/showData() via require, so they execute in function scope — the parameters $loginError / $errors / $dataArray are directly usable without extra plumbing.
  • header.php sits in the same directory; require_once 'header.php' falls back to the calling script's directory, so it always resolves.
  • isLoggedIn() / isAdmin() / usernameFromSession() are global functions, callable from any template.
  • CSS comes from the Bootstrap CDN and links start with / (site root = public/), which is why the server must run as php -S localhost:3000 -t public.
