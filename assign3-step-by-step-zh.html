1. 网站三层架构地图（先看懂文件之间是谁调用谁）

这个项目延续了课堂上 week05_demo/CH16 的 前端控制器（Front Controller）三层结构：

浏览器访问 http://localhost:3000/?action=xxx │ ▼ 【第 1 层：唯一入口 Front Controller】 public/index.php ──▶ 启动 Session、加载 src 四个文件、定义 DATA_FILE、按 ?action= 分发请求 │ ├──▶ src/sessionManager.php （管“人”：登录账号核对、存取 $_SESSION、isLoggedIn / isAdmin 权限判断） ├──▶ src/validation.php （管“验”：用 PHP filter 扩展校验表单 5 个输入项，返回 $errors 错误数组） ├──▶ src/file_utility.php （管“存”：readData 读 students.csv 二维数组、writeData 追加写入新记录） │ ▼ 【第 2 层：动作控制器 Action Controller】 src/action_controller.php ──▶ showHome() / showForm() / showData() 决定渲染哪个页面；processForm() 串联校验与落盘 │ ▼ 【第 3 层：视图模板 View Templates】（HTML 素材均取自 html_examples/ 静态参考文件夹！） templates/header.php ──▶ 所有页面共用的顶部蓝色导航栏（按登录/管理员身份动态显隐菜单） templates/home.php ──▶ 首页（未登录显示登录框+错误提示；已登录显示授权说明） templates/data.php ──▶ 数据页（user 和 admin 都能看：空文件提示 或 学生列表表格） templates/form.php ──▶ 录入表单页（仅 admin 可看：错误提示 + 粘性回显 + 保存后禁用控件）
❓ 初学者灵魂发问：为什么不能按文件名字母顺序写，或者一上来先写 form.php？
如果你一上来就去写最复杂的 form.php 或 validation.php，打开浏览器访问 localhost:3000 看到的永远是一片纯白屏（因为总入口 public/index.php 在原题里一行可执行代码都没有）！写了几百行没法在网页上测试，一旦报错根本不知道哪儿出了问题。
反过来，如果你先写 header.php 并在里面调用了 isAdmin()，却还没去 sessionManager.php 里定义 isAdmin()，PHP 会立刻报 Fatal error: Call to undefined function isAdmin() 崩溃！
正确的做法是：先造底层被依赖的小函数 → 点亮公共导航与首页 → 接通总入口路由（马上在浏览器看到网页亮起来！） → 再接通数据读取页 → 最后攻克表单验证与写入闭环。

💡 为什么要加 -t assign3_starter/public 把 public 设为网站根目录？
  1. 保证所有链接生效：你看老师在 header.php 和 html_examples 里写的超链接都是 href="/"、href="/?action=form"、action="/?action=login"（以斜杠 / 开头代表网站根目录）。只有把 public/ 设为根目录，访问 / 时 PHP 才会自动执行 public/index.php！
  2. 保护数据与源码安全：把 src/、templates/ 和 data/students.csv 放在 public/ 文件夹外面（上一级目录），外部访客就无法在浏览器输入 http://localhost:3000/data/students.csv 直接把全班学生隐私数据下载走！这是正规 PHP Web 项目的标准安全做法。

  • 学号正则 /^\d{10}$/：^ 代表字符串开头，\d 代表数字（0-9），{10} 代表恰好重复 10 次，$ 代表字符串结尾。合起来就是“从头到尾必须恰好是 10 位纯数字”，少一位、多一位、夹杂字母或留空都会返回 false！
