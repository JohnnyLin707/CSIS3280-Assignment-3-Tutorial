1. 项目概览与最终结构

作业要求做一个三页面 Web 应用：首页（登录）、数据录入表单（仅 admin）、数据展示（登录即可见），数据保存在 data/students.csv。整体采用课堂上 demo 的三层结构：

2. 请求是如何流转的（路由表）

index.php 用 switch ($action) 分发请求，与 week05 demo（CH16）的 front controller 风格一致：

URL处理效果
/ 或其它default → showHome('')未登录显示登录表单（图 1）；已登录显示授权说明文字（图 4）
/?action=login POSTprocessLogin()admin → 表单页（图 3）；user → 数据页（图 12）；失败 → 首页 + 错误提示（图 2）
/?action=login GETshowHome('')等同首页
/?action=form GET / POSTshowForm([]) / processForm(DATA_FILE)仅 admin 可进；user 或未登录一律回首页（图 12 说明）
/?action=datashowData(readData(DATA_FILE))任何登录用户可见（图 5、9、12）
/?action=logoutlogout()清空 $_SESSION 后回首页（图 11）
为什么 require 用 __DIR__ 拼路径：以 ../ 开头的相对路径只按"PHP 进程当前工作目录"解析，从不同目录启动服务器就会找不到文件；__DIR__ 永远指向文件自身所在目录，任何启动方式都稳妥。数据文件路径同理，定义为常量 DATA_FILE（index.php 中 define('DATA_FILE', __DIR__ . '/../data/students.csv')），这样 sessionManager.php 里的 processLogin()（签名固定、不能加参数）也能拿到它。

3.2 src/sessionManager.php — 登录/会话/认证/授权

原文状态：除 processLogin() 外全部写好。

  • 新增修改位置：processLogin() 内，$_SESSION['username'] = $username; 之后、原注释 // otherwise show the data page 之下的预留空白处：

  • 保留其余函数（getUsers、validLoginCredentials、usernameFromSession、isLoggedIn、logout）一字未动；没有删除任何代码

3.3 src/file_utility.php — 文件读写

原文状态：两个空函数 + 注释。

  • 新增readData()：先 file_exists() 检查，不存在直接 return [];（数据页据此显示图 5 的提示）；存在则 fopen(..., 'r') + fgetcsv 循环逐行读入二维数组，并跳过空行
  • 新增writeData()：先 file_exists() 检查，不存在则 touch() 先创建，再 file_put_contents($fileName, $str . PHP_EOL, FILE_APPEND | LOCK_EX) 追加一行
为什么 writeData() 要"先创建再写入"？题目注释原文是"文件不存在就不写任何数据"，但作业同时要求 students.csv 启动时不存在、图 10 又要求首次提交必须能保存——若严格照注释"不写"，第一次提交永远存不进数据。两处矛盾以图片行为为准，代码注释里已说明这个取舍。

3.5 src/action_controller.php — 动作控制器

原文状态：4 个空函数 + 注释（函数签名不可改）。

4. 原文代码删除/替换明细（直接回答"删了什么、在哪、为什么"）

结论先说：整个项目没有删除任何原题目注释；真正被替换掉的原文只有 templates/header.php 里的 2 处静态占位内容：

#文件与具体位置原文替换为为什么必须删/换
1 templates/header.php 第 14 行（<title> 标签内） Put title here <?= $pageTitle ?> 静态占位文字。starter 里每个模板都定义了 $pageTitle 却没人使用它，页头不改成动态输出，所有页面的 <title> 就都是同一句占位文字，与题目给的变量意图相悖。

其余情况都属于"补全"而非删除：

  • public/index.php、src/action_controller.php、src/file_utility.php、src/validation.php：原文是纯注释骨架（只有注释没有代码），按作业要求在注释下方把实现写出来，注释原样保留。

作业规定"You can not change the function signature in the provided files"——所以全项目没有改任何函数签名，没有删任何函数；需要"多传一个信息"时改用常量（DATA_FILE）或全局标记（$GLOBALS['formSaved']）解决。

5. html_examples → templates 套用指南（怎么拿代码才能生效）

html_examples/ 里的 5 个文件是静态效果图，帮你确认"最终渲染出来的 HTML 长什么样"；templates/ 里才是动态模板。两者关系：

html_examples 文件内容对应去向
template_header.html页头部分（导航 + 用户区）templates/header.php（starter 已给出主体，只需补条件与动态输出）
home_complete.html完整首页 = header + home 拼接后的最终效果用来核对 header.php + home.php 拼接结果是否一致
template_home.html首页下半部分（h1 + 错误框 + 登录表单）templates/home.php 的 body
template_form.html表单下半部分（错误框 + 表单）templates/form.php 的 body
template_data.html数据页下半部分（h1 + 表格）templates/data.php 的 body

通用四步法（静态 HTML → 生效的 PHP 模板）

  1. 定位片段：在 html_examples 里找到需要的静态块（错误框、表单、表格、导航项）。
  2. 粘进模板：复制到 templates/xxx.php 中 require_once 'header.php'; 之后、结尾 </div></body></html> 之前。粘进去不写 PHP 也能先跑出静态效果。
  3. 数据动态化：把写死的示例值换成 <?= $变量 ?>；把重复书写的行（option、表格行、错误 li）换成 foreach 循环。
  4. 加控制结构：用 <?php if ...: ?> ... <?php endif; ?> 控制"显不显示 / 选中 / 禁用"。

为什么"直接粘"就能生效

  • 模板是被 showHome()/showForm()/showData() 用 require 引入的，此时处于函数作用域，所以函数参数 $loginError / $errors / $dataArray 在模板里直接可用，不需要任何额外传递。
  • header.php 与各模板同目录，require_once 'header.php' 会按"调用脚本所在目录"兜底查找，必然命中。
  • isLoggedIn() / isAdmin() / usernameFromSession() 是全局函数，模板里随时可调用。
  • CSS 来自 Bootstrap CDN，链接以 / 开头（站点根 = public/），所以必须用 php -S localhost:3000 -t public 方式启动。

逐模板改造对照

目标模板取材位置改造点（示例 → 生效）
home.php template_home.html 第 3 行（h1）、15–48 行（formLogin 整块）；home_complete.html 第 65–71 行（form-control is-invalid 错误框） 错误框包进 if (!empty($loginError))，<li>Error message 1</li> 换成 <li><?= $loginError ?></li>；h1+表单包进 if (!isLoggedIn())，else 分支补图 4 的说明文字。
